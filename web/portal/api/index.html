REST API

Every table and view of the twin is an HTTP endpoint (PostgREST behind Kong, Supabase-compatible). Reads need only the public key below; writes need a signed-in account with the right role, exactly as on the data page — the database enforces the same rules for both.

Connection

Base URL

Auth/auth/v1/token
Public (anon) key

Sent as the apikey header on every request. It identifies this deployment, not a person, and only grants what anonymous visitors may do anyway. Unreal ships with it.

Reachable from the university network and the internet on port 443 only. The service-role key is never handed out; for writes, ask your team's curator for an account.

Things worth knowing

    
    
      
  • Use the public views (the endpoints listed below). Embedding across the base schemas
        (shared, trees, …) fails with PGRST200; the public views embed fine.
    • 
      
  • sensor_readings has tens of millions of rows — always filter by sensor_id
        and a timestamp range, or the request hits the statement timeout.
        For "latest value per sensor at time T" use rpc/ue_sensor_state_at.
    • 
      
  • Trees exist in several variants (field inventory, simulated time steps, scenarios). Filter by
        variant_id or use ue_trees / ue_variants to pick one forest state.
    • 
      
  • Geometries come back as GeoJSON and can be sent as EWKT, e.g. "SRID=4326;POINT(7.877 48.268)".
    • 
      
  • Model runs: POST rpc/request_job with {"workflow": "silva", "params": {…}},
        then poll job_status. Parameters per workflow are in workflows.param_schema.
    •
