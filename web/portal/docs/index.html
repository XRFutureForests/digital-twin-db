The data model in five sentences

  • A location is a research site (ECOSENSE, Mathisle); it holds plots, sensors and its climate and soil data.
  • A scenario is a management regime × climate pathway at one location, e.g. natural_growth or target_diameter_harvest_ssp585.
  • A variant is one forest state in a scenario: baseline_2025 is the field survey, silva_2030, silva_2035, … are SILVA projections in 5-year steps.
  • trees holds one row per tree per variant; tree_entity_id stays the same for one physical tree across all of them, and variant_type_id says whether a row was measured (1) or simulated (4). DBH is not on the tree row but in stems.
  • A sensor belongs to a location (and optionally to trees); a reading is sensor_id, timestamp, value — tens of millions of rows, so always filter by sensor and time.

How the core tables connect

Arrows point from the table that is referenced to the one that refers to it. Each name is also an API endpoint, /db/rest/v1/<name>.

Schemas

Seven base schemas hold the tables; the public schema exposes one view per table under the same name, which is what the API, the data page and Unreal use. Row counts are live.
